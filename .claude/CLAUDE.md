# FashionAgent 项目规范

> 本文件是项目级 CLAUDE.md，仅对 FashionAgent 项目生效。
> 全局聊天规范在用户主目录的 CLAUDE.md 中，与本文件不冲突。

---

## 一、开发环境

- conda 虚拟环境：`fashionagent`
- Python 版本：3.13
- 项目根目录：`F:/服装领域智能Agent`
- 业务数据库：SQLite（`data/fashion.db`）
- 向量数据库：Chroma（`data/vector_store/`）

---

## 二、开发前准备

- 开始新模块开发前，先读取 `docs/01-项目设计文档.md` 确认该模块的设计
- 确认该模块的输入输出和与其他模块的依赖关系
- 不清楚的地方先提问，不猜测

---

## 三、代码规范

遵循 `docs/07-开发规范.md` 中的全部规范，包括但不限于：

- 命名规范（snake_case / PascalCase）
- 类型注解（函数参数和返回值必须标注类型）
- 导入规范（标准库 → 第三方 → 本地，分组排序）
- 公共函数写 docstring
- 关键设计决策在代码中附注释说明原因

---

## 四、开发日志

- 每个功能模块完成后，更新 `docs/04-开发日志.md`
- 记录：完成内容、设计决策及原因、遇到的问题及解决方案
- 如果当前阶段无报错，也要记录"做了什么决定、为什么这么决定"

---

## 五、提交规范

### 提交时机

- 每个功能模块完成后提交一次，不攒多个模块一起提交
- 提交前更新对应的开发日志

### Commit 信息格式

```
<type>: <subject>

<body (可选)>
```

type 类型：feat / fix / docs / style / refactor / test / chore

### 提交流程

```
1. git add <相关文件>
2. git commit -m "规范的信息"
3. git push
4. 做阶段总结（口头或书面）
```

---

## 六、设计注释规范

AI 每完成一个关键模块的代码，须在代码中附带设计说明注释：

```python
# 关键设计说明
# ─────────────────────────────
# 为什么这么设计：
# - 原因1
# - 原因2
# 权衡：
# - 缺点/后续改进方向
# ─────────────────────────────
```

目的是让开发者通过阅读注释理解设计决策，而非只看代码本身。

---

## 七、禁止行为

- 不生成硬编码的 API Key
- 不直接删除或覆盖未确认的文件
- 不引入额外的第三方依赖（除非在需求中明确说明）
- 不修改 `docs/` 下的文档（除非开发者明确要求）
