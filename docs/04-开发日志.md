## 2026-07-19

### [ReAct 重构] 用 LLM 自主决策替代硬编码工具调度
**用时：** 约 20 分钟
**完成内容：**
- 创建 `app/tools/_registry.py`：工具注册表，定义 5 个工具的 OpenAI function-calling 格式描述（名称、参数 schema、前置条件），新增工具只需注册一行
- 创建 `app/agent/nodes/react_node.py`：ReAct 循环节点，LLM 自主决策→调用工具→结果反馈→再决策→最终回答，最大 5 轮迭代防循环
- 重构 `app/agent/graph.py`：删除 tool_node 和 refund_node，统一接入 react_node；路由简化：knowledge_query → RAG，其他所有意图（问候/工具/闲聊）→ ReAct，LLM 自主判断
- 精简 `app/agent/nodes/answer_node.py`：去除所有工具格式化逻辑，退化为纯兜底节点（只确保 final_answer 非空）
- 工具文件保留（tool_node.py / refund_node.py）不再被引用，标记为历史代码
**设计决策：**
- 用 OpenAI function-calling 格式而非自定义协议：DeepSeek 原生支持，参数结构化输出无需正则提取
- 退款三步交由 LLM 编排：query_order → risk_check → create_ticket，根据中间结果动态决策是否创建工单
- 系统 prompt 告知用户 ID，工具参数要求从上下文传递 user_id，避免越权
- 后端编译验证通过，节点结构：router → rag/react/answer → trace
**遇到的问题：** 无
**学到什么：**
- ReAct 的核心价值不是"用 LLM 做决策"这个技术动作，而是"新增工具不再改路由代码"——注册一行描述即可
- tool_node + refund_node 的旧架构让 LLM 变成了"翻译器"（自然语言→参数），ReAct 让 LLM 变成了"决策者"（评估情况→选择动作→分析结果）
- 回答生成从 Python 模板（_format_tool_reply）转移到 LLM 后，回复更自然，但也更难精准控制措辞——这是灵活性和可控性之间的经典权衡

### [Phase 3] LangGraph 工作流（state + router_node + rag_node + answer_node + graph）
**用时：** 约 30 分钟
**完成内容：**
- `app/agent/state.py`：AgentState TypedDict（10 个字段）
- `app/agent/nodes/router_node.py`：规则优先 + LLM 兜底的意图路由

- answer_node 统一回复出口：后续所有链路汇聚到这里

- payload 写入 JSON 文件再 curl -d @file
- main.py 中 import 时别名，FastAPI 实例改名 fastapi_app
**学到什么：**
- LangGraph 的 StateGraph 比想象中简单，核心就是 add_node + add_edge + compile
- 条件路由（add_conditional_edges）是实现多意图分派的关键

### [安全] Agent四层安全边界

**完成内容：**

- 新增Goal Guard，在Router、LLM和工具调用前阻断批量删除、权限绕过、凭证泄露等越权目标。
- 新增路由后Boundary Guard，区分只读、确定性退款、人工审批和禁止执行目标。
- ToolSpec增加动作类型、风险等级和审批标记；ToolFirewall默认只允许低风险只读工具。
- 增加最大推理轮数、最大工具次数、执行截止时间、LLM输出Token和单次LLM超时预算。
- 普通Human-in-the-loop请求写入unresolved_case人工队列；退款继续使用专用ticket，避免重复建单。
- Trace记录边界判定、审批要求、执行预算和人工队列编号。

**设计决策：**

- 安全边界由服务端策略执行，不依赖Prompt要求模型自律。
- LLM不拥有写入、删除、支付或外部发送权限；未来新增写能力必须建立独立确定性工作流。
- 目标守卫采用默认拒绝，高风险未知目标停止执行并交给人工。
