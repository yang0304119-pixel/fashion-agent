# 分层意图识别漏斗

FashionAgent 的意图路由采用以下执行链：

```text
服务端可信身份与卡片上下文
→ 高精度确定性规则
→ 上下文语义路由
→ LLM Planner
→ 只读工具或确定性业务工作流
→ 权限、归属和风险校验
```

## 第一层：确定性规则

规则层仅覆盖无歧义的高频请求，例如问候、转人工、明确退款动作、退款状态、订单查询、库存查询和待补参数。规则层以高精度为优先，不会因为出现“退款”“起球”或“质量问题”就发起退款。

示例：

```text
退款规则是什么      → knowledge_query
我的退款到哪了      → refund_status_query
帮我退订单10001     → refund_request
取消订单10001       → after_sales_request → 人工接管
```

## 第二层：上下文语义路由

规则未命中时，使用本地 BGE Embedding 对意图样例进行语义匹配，并结合：

- 当前消息
- 最近三轮同租户、同用户、同会话消息
- `pending_intent`
- 已收集槽位
- 服务端重新查询后的商品或订单上下文

语义路由支持多标签输出。当前默认阈值为：

```text
直接路由阈值       0.52
Planner 候选阈值  0.40
多意图分数差       0.05
```

这些数值只根据当前本地 BGE 的分数尺度和少量冒烟样例设置，是工程初始值，不代表已经达到某个准确率或流量覆盖率。上线或面试展示时应使用标注意图评测集校准，并报告实际混淆矩阵、准确率、召回率和各层命中比例。

## 第三层：LLM Planner

低置信度、多意图或复杂表达进入结构化 Planner。Planner 只返回意图、置信度、证据和澄清问题，不直接执行工具。

组合只读问题进入 ReAct，可调用：

- 商品搜索
- 商品与库存查询
- 订单查询
- 尺码推荐
- 当前租户线上知识库检索

`user_id` 和 `tenant_id` 不暴露给模型，由服务端注入。

## 高风险安全边界

退款、取消订单、换货、修改库存、改价和发货均不由 LLM 自主执行。

- 明确退款请求进入现有确定性退款工作流，重新校验租户、用户、订单归属、状态、金额、风险和幂等性；高风险退款仍需人工审批。
- 取消订单和换货当前只转人工，不修改订单。
- ReAct 注册表只包含只读工具。
- 模糊退款表达即使被语义模型或 Planner 预测成写意图，也会由路由保护逻辑降级为知识咨询或安全兜底。

## 可观测性

执行轨迹记录：

- `intents`
- `router_source`
- `router_evidence`
- `requires_planning`
- 最终工作流、工具结果和人工接管状态

因此运营台可以区分规则命中、语义路由、Planner 兜底和安全降级，并为后续阈值校准积累数据。
