# 知识库处理与审核流程

知识处理现在包含两条边界清晰的流程：

1. AI 客服运营台知识文档生命周期：上传、解析、内容修订和人工审核。
2. 现有线上 RAG 索引流程：继续使用已审核的全局 processed 文档和 Chroma 活跃集合。

第一阶段只完成第 1 条流程，不会因为运营台批准文档而自动修改线上 Chroma。

## 0. 运营台知识文档生命周期

管理员进入“AI 客服运营台 → 知识文档”，完成：

```text
上传商家资料
→ 创建 knowledge_document 和 knowledge_revision
→ 解析为 Markdown
→ 查看质量报告
→ 人工修订内容
→ 审核通过或拒绝
```

文件按服务端可信租户隔离保存：

```text
data/knowledge/tenants/{tenant_id}/documents/{document_id}/revisions/{revision_id}/
├── raw/
└── processed/
    ├── content.md（实际文件名随来源格式变化）
    └── quality-report.json
```

管理 API 不接受浏览器提交 `tenant_id`，统一使用 JWT 当前管理员所属租户。
修改解析内容后，原审核状态自动重置为 `pending`，必须重新审核。

核心接口：

```text
POST /api/admin/knowledge/documents
GET  /api/admin/knowledge/documents
GET  /api/admin/knowledge/documents/{document_id}
POST /api/admin/knowledge/revisions/{revision_id}/parse
GET  /api/admin/knowledge/revisions/{revision_id}/content
PUT  /api/admin/knowledge/revisions/{revision_id}/content
POST /api/admin/knowledge/revisions/{revision_id}/approve
POST /api/admin/knowledge/revisions/{revision_id}/reject
```

## 现有命令行索引流程

RAG 索引不直接读取 `data/knowledge/raw` 中的原始文件，而是使用人工批准的
`data/knowledge/processed` 内容。该流程在第二阶段接入候选知识库发布前保持不变。

### 1. 提取为可审核 Markdown

```powershell
python -m app.rag.processor extract
```

输出：

```text
data/knowledge/processed/
├── 按原目录保存的 Markdown
└── quality-report.json
```

PDF、DOCX、CSV 等文件会保留原扩展名并追加 `.md`，例如：

```text
退款与换货政策.pdf.md
羽绒服洗护指南.docx.md
商品目录.csv.md
```

重复执行 `extract` 默认不会覆盖源文件未变化的人工修订内容；使用
`--force` 会重新提取并把审核状态重置为 `pending_review`。

### 2. 人工检查和修正

检查 `processed` 中的 Markdown 和 `quality-report.json`，重点核对：

- 关键数字、期限和金额；
- PDF 多栏阅读顺序；
- 表格行列；
- 页眉页脚和重复内容；
- OCR 错字、乱码和缺失段落。

可直接编辑处理后的 Markdown。

### 3. 批准审核结果

批准单个来源：

```powershell
python -m app.rag.processor approve --source "售后规则/通用/退款与换货政策.pdf"
```

全部人工检查完成后批量批准：

```powershell
python -m app.rag.processor approve --all
```

查看状态：

```powershell
python -m app.rag.processor status
```

批准会记录当前处理文件的 SHA-256。批准后再次修改文件，索引器会拒绝构建，
必须重新批准。

### 4. 构建索引

```powershell
python -m app.rag.indexer
```

只有所有文档均为 `approved`、原始文件哈希未变化、处理文件哈希与审核记录一致时，
索引器才会写入新的 Chroma 集合。
