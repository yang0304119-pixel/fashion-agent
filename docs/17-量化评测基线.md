## 2. RAG 检索指标

### 2.1 口径

- 标注集：`data/evaluation/rag_cases.jsonl`，共 31 条。每条包含问题、标准来源和原文证据说明。
- 被测对象：当前持久化活跃索引 `fashion_knowledge_20260717155949_434be246`，包含 154 个 chunk、11 个唯一来源。
- 检索链路：项目实际 Dense + BM25 + RRF 融合代码；离线运行时关闭远程 LLM Query Rewrite，使用原查询，避免网络状态污染结果。
- 排名单位：严格使用检索器实际返回的前 K 个 chunk；同一来源的多个 chunk 会分别占据名次，和生产调用的 `top_k` 语义一致。
- `Recall@K = 前 K 个 chunk 覆盖的相关来源数 / 该问题全部相关来源数`。
- `Hit@K = 前 K 个 chunk 至少包含一个相关来源的问题数 / 总问题数`。
- `MRR@5 = 首个相关来源排名倒数的均值；前五未命中记为 0`。
- 检索异常不会从分母排除，按未命中计数。本次异常数为 0。

### 2.2 结果

| 指标 | 数值 | 原始计数或说明 |
|---|---:|---|
| Recall@1 | 59.41% | 对每题相关来源召回率取宏平均 |
| Recall@3 | 83.33% | 对每题相关来源召回率取宏平均 |
| Recall@5 | 87.63% | 对每题相关来源召回率取宏平均 |
| Hit@1 | 83.87% | 26/31；Wilson 95% CI 为 67.37%-92.91% |
| Hit@3 | 93.55% | 29/31；Wilson 95% CI 为 79.28%-98.21% |
| Hit@5 | 93.55% | 29/31 |
| MRR@5 | 0.8817 | 31 题全部进入分母 |
| 本机 CPU P50 / P95 | 19.81 / 32.71 ms | 本地 BGE、Chroma 和 154 chunk；不含网络、答案生成与并发排队 |

前五完全未命中的 2 个案例：

1. `RAG-PRODUCT-009`："羽绒服偶尔钻出几根绒算质量问题吗？"被知识类型推断限制到售后规则，未取回包含答案的商品知识。
2. `RAG-SIZE-005`："冲锋衣为什么建议选大一码？"被限制到商品知识，未取回尺码指南。

这两个案例说明当前主要问题不是知识库缺少答案，而是 `infer_knowledge_type` 单类型硬过滤造成跨类型漏召回。

## 3. 意图识别指标

### 3.1 口径

- 标注集：`data/evaluation/intent_cases.jsonl`，共 40 条，每个目标意图 4 条。
- 这些问法不复用 `semantic_router.py` 中的意图样例，降低把训练样例当测试样例的风险。
- 被测链路：高精度规则 + 本地 BGE 语义路由；远程 LLM Planner 显式禁用。
- 因此本节不能描述为完整线上漏斗准确率，只能称为“两层离线基线”。

### 3.2 结果与诊断

| 指标 | 数值 | 说明 |
|---|---:|---|
| Accuracy | 65.00% | 26/40；Wilson 95% CI 为 49.51%-77.87% |
| Macro-Precision | 77.27% | 按评测输出标签宏平均 |
| Macro-Recall | 59.09% | 按评测输出标签宏平均 |
| Macro-F1 | 61.53% | 避免高频类别掩盖弱类别 |
| 写意图 Precision | 100.00% | 3/3；Wilson 95% CI 下界仅 43.85%，样本仍少 |
| 写意图 Recall | 37.50% | 3/8；Wilson 95% CI 为 13.68%-69.43% |
| 实际 fallback 率 | 20.00% | 8/40，其中 4 条本来就是域外问题 |

路由来源分布：规则层 13/40（32.50%），语义层 19/40（47.50%），安全 fallback 8/40（20.00%）。这是均衡评测集上的来源分布，不是线上流量覆盖率。

各类正确数：尺码推荐 4/4、人工转接 4/4、域外 fallback 4/4；订单查询与退款状态各 3/4；知识和商品查询各 2/4；退款申请 2/4；库存查询 1/4；换货/取消操作 1/4。优先修复方向是：

1. 扩充明确退款、换货、换色和取消订单的高精度表达，同时继续保持写操作服务端校验。
2. 调整语义多标签 margin，减少单一库存或商品问题被误判为 `composite_query`。
3. 修正规则优先级，例如“指定订单的退款结果”不应先被普通订单查询截获。

## 4. 记忆与知识处理

`data/evaluation/memory-report.json` 包含 8 条案例：写入提取 2/2、安全拦截 2/2，召回命中、租户隔离、上下文预算和任务恢复各 1/1。六项汇总指标当前均为 1.0，但总体 8/8 的 Wilson 95% 置信区间仍为 67.56%-100.00%；单项 1/1 或 2/2 的不确定性更大，不能外推成生产准确率。

`data/knowledge/processed/quality-report.json` 包含 11 份文档：10 份 `passed`、1 份 `warning`、0 份 `failed`。警告来自羽绒服商品详解的重复行比例偏高。所有 11 份均为 `pending_review`，且报告生成时间晚于当前 legacy 活跃索引，因此“索引可检索”和“当前文档已审核发布”必须分开描述。

## 5. 自动化回归

2026-07-21 使用 Python `unittest discover` 运行 217 项测试，217 项通过、0 项失败、耗时 102.795 秒。测试覆盖接口租户边界、退款流程、知识生命周期、记忆、RBAC、工具恢复和本次新增指标计算等代码路径。

运行日志包含 FastAPI/Chroma/`datetime.utcnow()` 的弃用告警，以及测试用例故意制造的候选索引失败日志；这些没有导致测试失败。自动化测试通过率只用于说明回归状态，不能替代 RAG、意图、回答质量或线上 SLA 指标。

## 6. 当前不能给出数值的指标

以下指标合理，但仓库没有对应的真实标注或生产流量，当前只能定义口径，不能填写百分比：

| 指标 | 建议公式 | 缺少的事实数据 |
|---|---|---|
| 完整漏斗意图准确率 | 完整 Router 预测正确数 / 人工标注意图数 | 启用 Planner 后的固定输出与人工复核集 |
| Answer Groundedness | 被来源支持的事实断言数 / 全部事实断言数 | 逐断言人工标注或可靠评审器标注 |
| Tool Success Rate | 成功工具调用数 / 全部工具调用数 | 统一时间窗内的生产 Trace，且要按业务失败与系统失败分层 |
| Auto Resolution Rate | 无人工介入且用户问题解决的会话数 / 有效会话数 | 会话级解决标签、重开与重复咨询规则 |
| Human Review Trigger Precision/Recall | 与人工标注 `human_required` 对比 | 覆盖边界金额、质量争议、重复退款等场景的标注集 |
| P95 端到端延迟 | 用户请求总耗时的第 95 百分位 | 生产并发、网络、LLM、Provider 和排队耗时 |
| CSAT / 转人工率 / 重开率 | 按运营时间窗统计 | 真实用户反馈和线上会话事件 |
