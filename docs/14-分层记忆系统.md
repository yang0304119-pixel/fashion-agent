# FashionAgent 分层记忆系统

## 1. 当前实现

主链路：

```text
memory_load
→ router
→ memory_retrieve
→ RAG / ReAct / 确定性业务节点
→ answer
→ memory_commit
→ conversation_state
→ trace
```

记忆系统与RAG知识库、Agent Trace分离。所有读取和写入均使用服务端JWT得到的
`tenant_id + user_id`；订单、库存、价格、退款金额和业务状态不会作为长期记忆使用，
必须由业务服务重新查询。

## 2. 三层记忆

### 会话短期记忆

- `conversation_turn`保存用户、助手和工具结论。
- 最近Turn同时受数量和Token预算限制。
- 旧Turn压缩为`conversation_summary`，摘要保留来源Turn ID、目标、实体、完成动作和未完成任务。
- 原始Turn默认30天，摘要默认90天，可通过环境变量调整。

### 工作/任务记忆

- `task_checkpoint`保存目标、当前步骤、已完成步骤、槽位、工具结论、问题和下一步。
- 缺少参数、工具失败、等待业务状态和转人工都会保存检查点。
- 退款和人工接管属于关键任务，不依赖普通TTL自动删除。

### 长期记忆

- `memory_record`保存用户偏好、项目规则、验证事实、决策、失败模式、流程和长期目标。
- 明确用户偏好可以自动写入；动态业务事实、鉴权信息和支付信息禁止写入。
- 同一`subject_key`的新值会把旧值标记为`superseded`。
- `memory_event`记录创建、召回、去重、覆盖、修改、删除、过期等生命周期事件。

## 3. 两阶段检索

路由前只加载当前任务、会话窗口、摘要和少量稳定偏好。路由后根据意图过滤
`memory_type`，再使用关键词、可选BGE向量相似度、重要性、置信度、稳定性和新近程度
进行混合排序。Embedding不可用时自动降级为关系过滤与关键词排序。

长期记忆属于低优先级参考数据，不能覆盖系统规则或服务端业务校验。

## 4. 上下文预算与压缩

`MemoryContextBuilder`按以下优先级组装：

1. 任务检查点；
2. 服务端可信卡片上下文；
3. 最近会话Turn；
4. 历史摘要；
5. 按需召回的长期记忆。

每部分加入前估算Token，超过`MEMORY_CONTEXT_TOKEN_BUDGET`即停止继续注入。
工具原始结果不重复放入会话，只保存可控摘要。

## 5. 遗忘与治理

- 原始Turn和摘要使用TTL清理。
- 长期记忆支持过期、衰减、覆盖、软删除和用户纠正。
- 写入与修改统一拦截敏感信息、动态业务事实和指令型记忆投毒内容。
- 用户删除长期记忆时会清空正文、检索文本和Embedding，只保留不可还原的删除占位及审计事件。
- 路由后检索排除路由前已召回的记忆ID，避免重复注入和重复计数。
- 用户接口：`GET/POST/PATCH/DELETE /api/memories`。
- 会话接口：`GET/DELETE /api/memories/sessions/{session_id}`。
- 管理员只默认查看统计：`GET /api/admin/memories/stats`。
- 管理员可创建租户/项目级规则：`POST /api/admin/memories`。

消费者Sandbox的“我的记忆”面板支持查看、修改和删除长期记忆；运营台“记忆治理”
只显示当前租户类型、状态和生命周期事件统计，避免默认暴露用户正文。


## 7. 数据库迁移

```powershell
D:\CondaEnvs\fashionagent\python.exe scripts/migrate_memory_system.py
```

迁移脚本幂等创建`conversation_turn`、`conversation_summary`、`task_checkpoint`、
`memory_record`和`memory_event`。

## 8. 可计算评测

标注集：`data/evaluation/memory_cases.jsonl`

```powershell
D:\CondaEnvs\fashionagent\python.exe scripts/evaluate_memory.py
```

报告写入`data/evaluation/memory-report.json`。当前小型标注集覆盖写入提取、安全拦截、
召回Hit@K、租户隔离、上下文预算和任务恢复；结果只代表这些案例，不能外推为业务准确率。

当前回归证据：188项自动化测试通过；记忆评测集共8条案例，六项汇总指标均为1.0。
这些数字只证明当前代码与小型标注集通过，不代表线上业务准确率或生产SLA。

## 9. 部署边界

- 当前SQLite和Python内计算适合Demo及单实例。
- 多实例部署应把周期清理改为调度任务，并评估PostgreSQL/pgvector或独立向量服务。
- BGE不可用不会阻断客服请求，但语义召回会降级。
- 生产环境需要补充加密、数据保留合规和用户数据导出流程。
