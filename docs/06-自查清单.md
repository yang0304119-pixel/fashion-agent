# 自查清单

> 每个阶段完成后，对照清单检查自己是否真的理解了。
> 能口头回答这些问题，才算"学会了"。

---

## 阶段一：数据库 + 数据准备

**完成后自我检查：**

- [ ] 能不能画出当前项目的目录结构，说出每个文件夹的用途？
- [ ] 能不能说出项目有哪些数据库表，每张表存什么数据？
- [ ] 能不能说清楚 SQLite 和 MySQL 的区别，以及为什么开发阶段先用 SQLite？
- [ ] 如果现在要加一张"优惠券表"，你知道加在哪、怎么加吗？
- [ ] 种子数据里的订单状态有哪些？各代表什么含义？

---

## 阶段二：RAG 知识库

**完成后自我检查：**

- [ ] 能不能用一句话向不懂技术的人解释 RAG 是什么？
- [ ] 能不能说清楚"文档切分"的 chunk_size 改大改小分别有什么影响？
- [ ] 能不能说出 metadata 在 RAG 中的作用？
- [ ] 能不能画出 RAG 的完整流程（从原始文档到用户提问到返回结果）？
- [ ] 如果知识库从 10 个文档变成 10 万条数据，当前的方案有什么问题？

---

## 阶段三：Intent Router + LangGraph

**完成后自我检查：**

- [ ] 能不能说清楚 Agent 和普通聊天机器人的本质区别？
- [ ] 能不能画出用户输入进入系统后的完整流转图（从输入到回复经过哪些节点）？
- [ ] 能不能解释 State 在 LangGraph 里起什么作用？
- [ ] 为什么系统冷启动时不用训练模型来分类意图？那用什么方案？
- [ ] 如果用户说"这个衣服太大了我要退，顺便帮我查一下上次买的那个发货没"，系统怎么处理？

---

## 阶段四：Tool Calling

**完成后自我检查：**

- [ ] 能不能说清楚 Tool 和直接写一个 Python 函数有什么区别？
- [ ] 为什么工具输入输出必须结构化？
- [ ] 如果调用订单查询时数据库连不上了，系统应该怎么处理？
- [ ] 能不能说出当前项目里哪些 Tool 是低风险、哪些是高风险，为什么？

---

## 阶段五：退款流程闭环

**完成后自我检查：**

- [ ] 能不能说清楚为什么退款不能全自动，一定要人工审核？
- [ ] 能不能说出 risk_check 判断风险时考虑了哪些因素？
- [ ] 如果用户申请退款的金额刚好 100 元，系统怎么处理？
- [ ] 如果用户已经退过款的订单又申请一次退款，系统怎么处理？

---

## 阶段六：Trace + 评测

**完成后自我检查：**

- [ ] 能不能说出 Agent Trace 记录了什么字段？排查问题时怎么用？
- [ ] 能不能解释 RAG Top-1 Recall 和 Top-3 Recall 的区别？
- [ ] 如果 RAG 召回率低，可能是什么原因？优化方向有哪些？
- [ ] 自动处理率这个指标代表什么？越高越好吗？有什么副作用？

---

## 最终总结

- [ ] 能不能在 30 秒内向面试官说清楚这个项目是做什么的？
- [ ] 能不能画出完整的系统架构图（不需要多精确，核心模块和流程对就行）？
- [ ] 能不能说出这个项目的三个核心亮点？
- [ ] 能不能说出如果现在要对接真实企业数据，需要改哪些地方、不需要改哪些地方？

---

> 使用方法：每完成一个阶段，对照清单逐条检查。
> 不能回答的，回去翻文档或查资料，直到能回答为止。
